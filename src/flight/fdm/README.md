# PC-7 flight dynamics subset

Reference: [JSBSim-Team/jsbsim](https://github.com/JSBSim-Team/jsbsim/tree/3f153c18a2518f8472e37c89e70444b1c671b700), commit recorded in `aircraft-pc7.json`. The upstream `COPYING` is copied verbatim as `LICENSE-JSBSim.txt`. No FlightGear code is used.

The PC-7 is a propeller-powered aerobatic trainer with six aerodynamic axes, a 10.40 m span and complete mass/inertia data. Its Aeromatic configuration explicitly describes an educational ALPHA model, not manufacturer-validated flight data. It is a better fit for this aircraft than an airliner or a non-aerobatic Cub. The source XML files are `aircraft/pc7/pc7.xml`, `aircraft/pc7/Systems/Conventional Controls.xml` and `aircraft/pc7/Engines/PT6A.xml`.

The JSON contains the source's 13 aerodynamic tables and 21 scalar derivatives, converted geometry/mass/inertia and engine rating. Conversion factors: ft = 0.3048 m; lb = 0.45359237 kg; slug ft² = 1.3558179483314004 kg m²; hp = 745.6998715822702 W; lbf = 4.4482216152605 N. Flight mass includes the configured payload and both initial tank contents. Source span is scaled to 10 m, with area proportional to scale², mass to scale³ and inertia to scale⁵.

`table.ts` ports FGTable's clamped linear and bilinear lookup. `atmosphere.ts` ports ISA layers and geometric/geopotential conversion from FGStandardAtmosphere. `model.ts` uses FGAerodynamics wind-to-body forces and coefficient moments, FGAccelerations' body velocity and diagonal rigid-body inertia equations, and a normalized quaternion increment corresponding to FGPropagate. The simulated body is X forward / Y right / Z down, mapped into PlayCanvas local axes as `(Y, -Z, -X)`. Rates `(p,q,r)` map to local quaternion axes `(q,-r,-p)`. There is independent body velocity, so the flight path need not coincide with the nose.

The subset uses a flat, nonrotating world and constant mass/inertia. It omits Earth rotation, fuel burn, landing gear/flaps/ground effect, alpha-dot derivatives, Reynolds-dependent stall yaw initiator, propwash and engine/propeller RPM dynamics. Forces act at the center of gravity; the source aerodynamic reference offset remains in the JSON for provenance. Propulsion is a density-adjusted power/airspeed approximation capped by the source static thrust. Outside the source's limited alpha coverage, a flat-plate blend supplies forgiving post-stall behavior. This is a JSBSim-derived educational subset with arcade assistance, not a full JSBSim engine or a validated PC-7 simulation.

`ASSISTS` at the top of `model.ts` controls effective mass, power/throttle curve, drag, maneuver lift, surface authority, body-rate assistance and a 70 ms input response. Rate assistance damps angular velocity, not bank angle. Neutral aerodynamic trim follows airspeed; it does not command wings level. Assistance forces intentionally do not preserve the original aircraft's lift/drag relationship. The speed is integrated from forces without an artificial minimum speed. The controller preserves the existing collision samples, spawn and boundary/ceiling safety guards, with a 120 Hz accumulator and a 250 ms frame cap.

Tests cover lookup boundaries and source knots, ISA checkpoints, normalized quaternions, neutral flight for 30 s (500 ±20 m and 65–80 m/s), a full elevator loop, aileron roll, simultaneous controls, reset/validation, render frame-rate independence, wing-only collision/respawn and world containment. Run `npm.cmd test` from the project root. Browser feel and agreement with the full C++ JSBSim are separate checks.

`instructor.ts` adds mouse guidance when `FlightState.controlMode` is `mouse`. The camera supplies a world direction; the instructor transforms it into the body frame, commands bank toward the target heading and uses damped pitch/yaw errors to point the nose at the aim. Rear targets retain a turn side across the ±180° seam and wait for bank before pulling. Returning the aim to the nose levels the wings. `INSTRUCTOR` holds PD gains, the 65° target bank limit and the 0.35 keyboard trim mix. Keyboard mode bypasses guidance entirely. Neither throttle nor camera fields are written by the instructor. Additional tests cover right/up/rear targets, settling, wing leveling, invalid aim and keyboard mixing/bypass.
